## 0. このファイルの使い方（セッション開始時に必ず読む）

本プロジェクトは複数のセッションに分かれて実装される。
**新しいセッションを始めたら、まず §1「現在地」と §4「申し送り事項」を読むこと。**

### セッション開始時の手順

1. §1「現在地」で、直前のセッションがどこまで進めたかを把握する
2. §4「申し送り事項」で、引き継ぎ事項・注意点を確認する
3. §5「未解決事項」で、判断待ちの項目がないか確認する
4. §2 のタスク表から、状態が `TODO` かつ依存が満たされている最小IDのタスクを選ぶ
5. [SPEC.md](SPEC.md) の該当セクションを読んでから着手する

### セッション終了時の手順（必須）

1. 完了したタスクの状態を更新し、チェックボックスを埋める
2. §1「現在地」を書き換える（**サマリはここだけを見れば分かる状態に保つ**）
3. §3「セッションログ」に1行追記する
4. 引き継ぐべき注意点があれば §4 に追記する
5. 仕様に変更・追加が生じたら **SPEC.md を更新する**（実装だけ進めて仕様を放置しない）
6. コミットする

### 状態の凡例

| 記号 | 状態 | 意味 |
|---|---|---|
| `TODO` | 未着手 | まだ手をつけていない |
| `WIP` | 作業中 | 着手済み。未完了のままセッションが終わった場合は §4 に残作業を書く |
| `DONE` | 完了 | 完了条件をすべて満たし、テストが通っている |
| `BLOCKED` | 停止 | 依存または判断待ちで進められない。理由を §5 に書く |
| `SKIP` | 見送り | 実施しないと決めた。理由を備考に書く |

## 4. 申し送り事項

セッションを跨いで引き継ぐべき事項。**解決したら取り消し線ではなく削除し、§3 のログに結果を書く。**

### 実装時に忘れやすい制約

1. **需給データを AI に送らない。** プロンプト組み立ては `app/ai/prompt.py` の1関数に集約し、
   需給テーブルを引数で渡せない型にする。`test_ai_prompt.py` で固定する（SPEC §7.2）
2. **UI で「信用残」と単独表記しない。** 日証金から取るのは貸借取引残高であって信用取引残高ではない。
   ラベルは「貸借取引残高（日証金）」とし、貸借銘柄のみが対象である旨を併記する（SPEC §1.4）
3. **`createSeriesMarkers` を複数回呼ばない。** 既存の売買シグナルと開示イベントを
   同一配列にマージして1回で設定する。分けて呼ぶと後勝ちで消える（SPEC §2.5.3）
4. **需給データを線形補間しない。** whitespace data ＋ `lineType: 2`（階段状）。
   補間すると存在しない日の値を捏造することになる（SPEC §2.5.2）
5. **`short_totals` は本ツールの算出値**であってサイトの公表値ではない。画面に注記する（SPEC §2.2.3）
6. **APIキーをログに出さない。** URL をログ出力する箇所では `Subscription-Key` を必ずマスクする
7. **`scrape_contact` 未設定ならスクレイピングしない。** 連絡先を名乗れない自動取得は行わない
8. **EDINET の `secCode` は5桁**（4桁＋末尾0）。突合時に変換が必要
9. **EDINET CSV は UTF-16LE のタブ区切り。** 拡張子が .csv でも普通の CSV として読むと壊れる
10. **Gemini の RPM/TPM/RPD をコードに埋め込まない。** 公式に数値表が無く変動が激しいため設定値とする

### 外部アクセスの作法

- 開発中にテストのたびに外部サイトを叩かないこと。**フィクスチャを1回採取して以後はそれを使う**
- 実通信テストは `CHRONOS_LIVE=1` のときだけ動くようにする
- karauri.net への手動確認も最小限に留める
