## 3. 前提情報

### 3.1 プロジェクトの目的

日本株の個別銘柄について、株価・テクニカル指標・需給（空売り残高／貸借取引残高）・法定開示を
1つのチャート上で突き合わせるローカルGUIツール。
任意のタイミングで Gemini API による分析レポート（HTML）を生成する。

### 3.2 土台

`satsuki19980613/Autotechnical` をクローンして使う。
pywebview + yfinance + SQLite + Lightweight Charts v5.2.1 の構成で、
テクニカル指標15種・複数pane・マーカー・pytest 約1,600行が既に存在する。

### 3.3 環境

- Windows 11 / Python 3.10+ / 完全ローカル動作
- ビルドツールなし。フロントは素の HTML/CSS/JS（ライブラリは同梱）

### 3.4 ユーザーが既に決定した事項（再議不要）

以下はユーザーが選択肢を提示された上で明示的に決定した。
**事実誤認が根拠になっている場合を除き、蒸し返さないでほしい。**

| # | 決定 |
|---|---|
| 1 | 信用残は**日証金CSV＋karauri.net の併用**で取得する（JPX週次PDFのパースも J-Quants 課金もしない） |
| 2 | Gemini には**株価・指標・EDINET開示のみ**送る。**需給データは送らない** |
| 3 | 適時開示は **EDINET のみ**。TDnet（上方修正・決算短信）は対象外とし、後から差し込める構造にする |

ただし、**決定の根拠となった事実そのものが誤っている**場合は指摘してほしい。
例：「karauri.net に銘柄別の信用残の時系列は無い」という前提が実は誤り、など。

### 重要度の基準

| 重要度 | 基準 |
|---|---|
| **重大** | このまま実装すると動かない、法的・規約上の問題がある、大きな手戻りが発生する |
| **中** | 実装は可能だが後で困る。設計の見直しが望ましい |
| **軽微** | 直した方がよいが実装しながらでも対応できる |
| **提案** | 問題ではないが、より良い案がある |
